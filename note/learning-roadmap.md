### 排序依据

- **Pinctrl & GPIO** → 所有外设的基础，SoC 引脚配置与数据读写
- **中断子系统** → 几乎所有外设驱动依赖中断机制
- **DMA** → UART/SPI/I2C/Audio 都可能用 DMA 加速，先理解数据搬运机制
- **UART → SPI → I2C** → 低速串行总线，由简到繁
- **PCIe → USB** → 高速总线，更复杂的协议栈
- **DRM → Audio → V4L2** → 多媒体子系统，依赖中断/DMA/总线
- **以太网** → 相对独立，最后攻坚

## 阶段四：C++ 与 NES 模拟器

> P1 优先级。自己写一个 NES 模拟器，跑在开发板上。有现成教程，预计两个月。
> GBA 模拟器不在此阶段计划内，留到 35 岁后有余力再看。

- **C++ 学习路径**：驱动开发中已经积累了一定的 C 基础，C++ 面向对象、模板、STL 是主要新学内容
- **模拟器项目**：跟着教程写 NES 模拟器，理解 CPU（6502）模拟、PPU 渲染、中断时间精度等——这和写内核驱动是互补的技能（驱动是"用硬件实现功能"，模拟器是"用软件模拟硬件"）
- **与现有知识结合**：模拟器跑通后，可以通过 DRM/KMS 直接渲染帧缓冲，通过 Audio 子系统输出音频，通过 GPIO 读取输入——打通驱动层到应用层的全链路

## 阶段五：Qt UI & 硬件设计

> P2 优先级，有余力再做，不设硬性 deadline。

- **Qt UI**：嵌入式 Qt 常见于工控和消费电子。结合项目方向可做一个游戏前端 UI 或调试控制面板。用到再查，不专门铺时间学
- **载板设计**：外购 ST 官方 SOM（核心板），自己设计底板引出 USB/HDMI/Audio/ETH/SD 卡槽。有了完整的 Batocera 移植经验后，设计自己的载板让 Batocera 跑在自己做的板子上，是很有成就感的闭环项目
- **核心板设计（GBA 模拟器）**：CPU + DDR + PMIC + eMMC 最小系统。BGA 焊接、DDR 信号完整性、多层板叠层设计门槛高。留到 35 岁以后条件成熟再考虑
